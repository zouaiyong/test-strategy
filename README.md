# test-strategy

分析项目或模块的测试策略与分层取舍（单测 vs 真库 SQL / 接口联调 vs 页面手工测试），产出可执行测试策略报告。本仓库是给 AI Agent 读的规则，不是测试执行框架。

装好后对 Agent 说「出个测试策略」「还需要做哪些测试」「要不要做接口测试」「哪些用单测哪些用手工」「接下来怎么开始测」即可。Agent 会先让你选评估范围，再按 `SKILL.md` 与 `references/report-template.md` 生成测试策略文档。

核心原则是不硬凑：不需要做的测试直接判「不需要」，禁止照着接口文档把所有接口列一遍；凡是列出的待测项，都写清前置数据、操作步骤、预期结果。

不覆盖：从 PRD 设计功能用例（用 `testcase-design`）、编写自动化单测代码（用 `testcase-to-unittest`）、完全无源码且无接口文档的探索性测试。细则以 `SKILL.md` 为准。

## 安装

```bash
npx skills add zouaiyong/test-strategy
```

会装到 `~/.agents/skills/test-strategy`。WorkBuddy、Claude Code 不读这个目录，装完后让对应 Agent 把该路径软链接到自己的 skills 目录（WorkBuddy：`~/.workbuddy/skills/test-strategy`；Claude Code：`~/.claude/skills/test-strategy`）。Windows 建不了软链接就用目录联接。链好后新开一轮对话即可被发现。

也可以把本仓库直接放到上述目录。目录里必须有 `SKILL.md`。

## 使用

把被测代码所在的项目交给 Agent（可附带 Swagger / Knife4j / OpenAPI 接口文档或 `*-自动化覆盖矩阵.md`），并指定一种评估范围：

1. **仅评估当前分支改动**（常用）：对比主干分支（`origin/master` 或 `origin/main`）的增量与公共代码调用波及面，剔除无关老模块
2. **评估全量代码**：扫描整个仓库所有模块，适合新项目整体提测或老项目全盘摸底

没说评估范围时 Agent 会先弹窗询问，不会擅自开扫。没给接口文档或功能用例时，Agent 直接读本地 `Controller` 与源码，不会停步向你索要文档。

已有单测和覆盖矩阵时，Agent 会扫「四态清单表」和「半自动化 TC 备注缺口」分流剩余工作；还没写单测时，会从源码中挑出建议优先补单测的核心类与方法，并反推页面人工必测项。

默认写到被测项目的 `doc/testcases/{项目或模块}-测试策略.md`。指定了目录就写到该目录。

## 产物长什么样

报告固定 7 节：`1. 一句话结论` → `2. 现状与范围盘点` → `3. 第一层：规则与纯口径单测（含明确不需要做的测试）` → `4. 第二层：真库与外部联调必验清单` → `5. 手工串联主链路` → `6. 第三层：纯人工与阻塞专项` → `7. 下一步行动顺序`。

**一句话结论与不硬凑声明**：

```markdown
## 1. 一句话结论（不硬凑）
- **评估模式**：【仅当前分支改动（`feature/xxx` vs `origin/master`）】
- **项目/改动特征**：重计算规则 + 少量聚合 SQL
- **明确不需要做的**：计费阶梯与参数校验已被 42 条单测锁死，Controller 仅为 1～3 行纯透传，不需要再写 HTTP 接口自动化脚本；未改动的档案模块零波及，本次无需回归。
- **真正还需要做的**：① 处理 2 条单测红灯判据偏差；② 在测试环境走一遍 4 步手工主链路（顺带验完 3 处手写 XML 与软删重加唯一键）；③ 点完 6 类页面纯人工专项。
```

**第二层真库盲区表**（4A 手写 XML/注解 SQL、4B 复杂 Wrapper/`lambdaUpdate` 置空、4C 软删唯一键/`saveBatch` 事务）：

```markdown
| # | 盲区类型 | 代码位置 | 关联 HTTP 接口 / 页面入口 | 为什么必须真库验 | 具体怎么做（前置数据 → 操作步骤 → 预期结果） |
|---|---|---|---|---|---|
| 1 | 4A 手写 XML (`UNION ALL`) | `BillDAO.xml#selectSummary` | `POST /bill/summary`（账单汇总 Tab） | `LEFT JOIN` + `UNION ALL` 与手写 `is_deleted=0` 在单测中被 Mock | **前置**：准备 1 条已对账、1 条已软删账单<br>**操作**：进入账单页切到汇总 Tab 按月筛选<br>**预期**：汇总金额不含已删记录，SQL 无语法报错 |
| 2 | 4C 软删重加唯一键 | `RuleBizService#save` | `POST /rule/delete` + `/save` | `@TableLogic` 软删后同编码新增是否撞 `uk_rule_code` | **前置**：已有编码为 `R01` 的规则<br>**操作**：页面删除 `R01` 后，立刻用 `R01` 重新新增<br>**预期**：新增成功，不报唯一索引冲突 |
```

**手工串联主链路与第三层 6 大类人工专项**：主链路按 `Step 1 → Step N` 剧本式编排，去测试环境页面走一圈即可一鱼两吃验完路由、真库 SQL、外部下拉框与状态流转；第 6 节固定承接「真实文件往返、前端默认筛选值、动态表单显隐、终态按钮置灰与弹窗、Tooltip/日志弹窗、无实现-阻塞核查」6 大类。

## 常见问题

**还没有写单测或功能用例能用吗？** 能。Agent 会直接扫描源码揪出高价值单测目标（算钱算量、精度进位、状态拦截、导入校验），并从源码条件分支与 PO/Enum 特征反推出 6 大类页面人工必测项。

**没给 Swagger / 接口文档会卡住吗？** 不会。未提供线上接口文档时直接读本地 `Controller` 注解提取接口；提供了线上文档则会额外比对本地与线上的接口漂移（如提示测试环境尚未部署最新代码）。

**为什么很多接口不建议写接口自动化？** 算钱算量与复杂校验下沉到单测几秒跑完且幂等；纯透传 Controller 的内部管理后台接口直接走页面手工主链路就能连路由、JSON 序列化、真库 SQL 一起验完，不重复造接口脚本。

**单测里有红灯（失败用例）时怎么处理？** 保持断言跟用例走、不改绿。报告会把 `*-判据偏差清单.md` 列为第一步最高优动作（先找开发修代码或找产品定基线），不会用新增其他测试来掩盖偏差。
