# test-strategy

分析项目或模块的测试策略与分层取舍（**单测 vs 真库 SQL / 接口联调 vs 页面手工测试**），产出带**前置数据、操作步骤、预期结果**的可执行测试策略报告。本仓库是给 AI Agent 读的规则，不是测试执行框架。

**核心原则：不硬凑。** 不需要再做的测试直接判「不需要」，禁止为了显得全面而照着接口文档把所有接口列一遍；但凡列出来的待测项，必须写清**「① 先准备什么数据、② 在页面点哪里（或调哪个接口/Job）、③ 看到什么现象算通过」**。

可单独对着项目源码使用，也可承接 `testcase-design`（功能用例）与 `testcase-to-unittest`（单测与自动化覆盖矩阵）的产物评估剩余测试工作。完整 6 步白盒摸底流程与五条取舍尺子见 [SKILL.md](SKILL.md)，报告落盘结构见 [references/report-template.md](references/report-template.md)。

## 安装

```bash
npx skills add zouaiyong/test-strategy
```

会装到 `~/.agents/skills/test-strategy`。WorkBuddy、Claude Code 不读这个目录，装完后让对应 Agent 把该路径软链接到自己的 skills 目录（WorkBuddy：`~/.workbuddy/skills/test-strategy`；Claude Code：`~/.claude/skills/test-strategy`）。Windows 建不了软链接就用目录联接。链好后新开一轮对话即可被发现。

也可以把本仓库直接放到上述目录。目录里必须有 `SKILL.md`。

## 怎么用

对已经加载本 skill 的 Agent 说「出个测试策略」「还需要做哪些测试」「要不要做接口测试」「哪些用单测哪些用手工」「接下来怎么开始测」，并指向被测代码所在的项目。

### 1. 先选评估范围

若提问时未指明范围，Agent 会先弹窗让你二选一（未选定前不会开扫）：

1. **仅评估当前分支改动（相对主干分支 `origin/master` 或 `origin/main` 的增量与波及范围）**（推荐）：适合日常迭代提测、特性分支开发完成后看本次要测什么。自动覆盖已提交改动、未提交工作区修改、未追踪新源码文件，并反向追查公共工具类/枚举/Entity/共用子方法的调用波及面，剔除无关老模块。
2. **评估全量代码（整个仓库所有模块）**：适合新项目整体提测、接手老项目做全盘测试摸底。

### 2. 支持的输入组合（无需凑齐文档即可开工）

- **单测与覆盖矩阵（可选）**：
  - **已有单测与 `*-自动化覆盖矩阵.md`**：自动盘点已跑/红灯条数，同时扫「四态清单表」和「覆盖矩阵明细表」里的半自动化 TC 备注缺口，精准分流到第二层（真库联调）或第三层（纯人工与阻塞专项）。
  - **尚未写单测（仅有项目源码）**：不会跳过第一层，而是直接扫描源码揪出高价值单测目标（算钱算量公式、精度进位、阶梯匹配、状态机拦截、导入逐行校验），列出「建议优先补单测的核心类与方法清单」，并从源码特征反推人工必测项。
- **线上接口文档（可选）**：
  - 提供了 Swagger / Knife4j / OpenAPI 时，自动比对本地 `Controller` 与线上接口漂移（如识别测试环境是否尚未部署最新分支代码）。
  - 未提供接口文档或功能用例时，直接读本地 `Controller` 注解与源码半成品痕迹（注释掉的接口、悬空方法、`TODO / FIXME`），不会停步索要文档。

## 三层测试策略与五条取舍尺子

### 三层切分模型

| 层级 | 测什么 | 首选手段 |
|---|---|---|
| **第一层：规则与纯口径层** | 公式计算、精度舍入、阶梯/区间判定、前置状态拦截、字段组合校验、导入文件逐行校验 | **单测**（直接调计算类 / 导入处理器 / 业务 Service + Mock DAO） |
| **第二层：真库 SQL 盲区 + 外部联调 + 主链路** | ① **4A** 手写 `mapper/*.xml` 与注解 SQL（多表 `JOIN` / `UNION ALL` / 动态标签 / 聚合统计）；② **4B** Java 层复杂 Wrapper（`.apply/.last/.or` 优先级）与链式 `lambdaUpdate` 置 `null`/条件被吞；③ **4C** 软删除 + 唯一索引删后重加冲突与 `saveBatch` 主子表事务；④ 覆盖矩阵备注中的 `集成层 / 本层验不了` 缺口；⑤ 定时任务 Job / MQ / 外部 Client 联调与核心状态流转闭环 | **内部管理后台默认用「页面手工走主链路」代替接口脚本**；仅在无源码、无前端页面、难造数据/无页面入口、对外接口契约、高频回归固化 5 种情况下动用接口测试 |
| **第三层：纯人工与未自动化专项** | ① 真实文件往返（导入/导出/模板下载）；② 前端默认筛选值与控件形态（后端不兜底）；③ 动态表单联动 / 字段显隐 / 动态列；④ 终态按钮置灰/隐藏 & 二次确认弹窗；⑤ 只读详情 / Tooltip / 状态标签颜色 / 操作日志弹窗；⑥ `无实现-阻塞 / 判据未定` 专项核查 | **页面人工测试**（兼容从覆盖矩阵提取与从纯源码特征反推） |

### 五条取舍尺子

1. **单测和接口测试都能测的，100% 选单测**：算钱算量、精度进位、状态流转、组合校验一律下沉到单测，严禁再用 HTTP 接口自动化重测一遍。
2. **薄 Controller + 已有规则层单测 = 不铺全量接口测试**：1～3 行纯委托透传的 Controller 不专门写接口契约脚本。
3. **单测 Mock 了 DAO 与外部 Client = 必须揪出持久层三大盲区与外部联调**：逐个读完范围内所有 `mapper/*.xml`，Grep 必搜 `.apply(`、`.last(`、`.or(`、`lambdaUpdate(`、`saveBatch`，并反查到 HTTP 接口或 Job 入口。
4. **内部管理后台接口，优先用「页面手工走主链路」代替写接口脚本**：去测试环境页面走一遍正向闭环，一鱼两吃同时验完路由、序列化、下拉框、真库 SQL 与页面交互。
5. **单测已红的「判据偏差」列为第一优先跟进项**：先拿着 `*-判据偏差清单.md` 找开发修代码或找产品定基线，不开新测试掩盖问题。

## 交付物

默认落盘到**被测项目**的 `doc/testcases/{项目或模块}-测试策略.md`（按 [references/report-template.md](references/report-template.md) 生成），包含 7 节：

1. **一句话结论（不硬凑）**：评估模式、代码特征、明确不需要做的测试、真正要做的 1～3 件核心动作。
2. **现状与范围盘点**：各模块接口数、功能用例数、单测条数（含红灯数）及当前卡点/漂移。
3. **第一层策略（规则与纯口径单测）**：已锁死模块声明或「建议优先写单测的类与方法清单」，以及明确【不需要做】的测试列表。
4. **第二层（真库与外部联调必验清单）**：
   - `4.1` 持久层真库盲区逐条核验表（4A / 4B / 4C 代码位置 ↔ 关联接口/页面 ↔ 前置数据、操作步骤、预期结果）
   - `4.2` 非 HTTP 入口（定时任务 Job / MQ）与外部服务（Client）联调表
5. **第二层 + 第三层合并执行：手工串联主链路**：剧本式 `Step 1 → Step N` 闭环步骤（分支模式只串改动与波及节点）。
6. **第三层（纯人工与阻塞专项）**：6 大必查类别全承接，附具体点击位置与核对要点。
7. **下一步行动顺序**：按优先级排序的落地步骤。
