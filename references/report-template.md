# 测试策略落盘模板

默认写入 `doc/testcases/{项目或模块}-测试策略.md`；分支模式建议带分支名 `doc/testcases/{模块}-{分支名}-测试策略.md`，避免多次迭代互相覆盖。项目无 `doc/testcases/` 则先创建；用户指定了目录就写到该目录。

**每一行待测项都由三部分组成：① 先准备什么数据、② 在页面点哪里（或调哪个接口/Job）、③ 看到什么现象算通过。** 测试同学拿到就能照着做，不需要再回头读代码；缺任何一部分这一行就还没写完。

**章节按「测试执行优先」排序**：测试同学直接从 `§1` 读到 `§4` 即可完成全部手工与真库测试；`§5`（L1 单测建议与免测边界）和 `§6`（模块与接口盘点）沉底供开发与备查。

**`§2 主链路`、`§3 真库盲区`、`§4 人工专项` 去重铁律（严禁同一动作抄三遍）**：
1. **`§2` vs `§3.1`**：凡是走 `§2 手工主链路` 就能顺手触发的真库 SQL 盲区，页面点击步骤只在 `§2 Step X` 写一次；`§3.1` 保留该行，但「具体怎么做」列写成 **`操作：随 §2 Step X 一起触发，不单独重走页面`**，只写该 SQL 额外要求的数据前置与落库字段核对。只有主链路顺手覆盖不到的独立盲区（如软删重加、开关正反切）才标 **`【独立加测】`** 并在 `§3.1` 展开完整步骤。
2. **`§3.1` vs `§3.2`**：同一次页面点击同时触发 4A/4B/4C SQL 和 MQ/Client 的，合并在 `§3.1` 同一条写完，不在 `§3.2` 拆第二行。`§3.2` 只单列无页面入口的 `@XxlJob` / MQ 消费者，或需单独造异常入参的 `Client`。
3. **`§2` vs `§4`**：`§4` 保留六大类 6 行骨架，但已在 `§2 Step X` 完整验过的类别直接写 **`已在 §2 Step X 覆盖，无额外独立项`**；本次改动完全不涉及的写 **`本范围无此类改动`**，严禁为填满表格编造凑数项。

编号约定：`§N` = 本报告第 N 节；`SN` = whitebox-recon 第 N 步；`L1/L2/L3` = 三层模型。

## 模板正文

```markdown
# {项目或模块} 测试策略与可执行分工清单

## §1 一句话结论
- **评估模式**：【仅当前分支改动（`{当前分支}` vs `{基准主干}`）】或【全量代码评估】。（非交互环境默认分支模式时，在此行标注「未经用户确认，默认按分支模式」）
- **项目/改动特征**：重计算规则 / 重复杂 SQL / 简单 CRUD / 外部接口联调（可组合）。
- **明确不需要做的**（全报告只在此处写一次，后文不重复）：
  1. **不需要用 HTTP 接口测试穷举 L1 的计算/校验分支**：单测已覆盖（或应由 `§5` 单测覆盖），页面主链路跑 1 组代表数据即可。
  2. **不需要为纯透传 Controller 写接口契约脚本**：点明具体 Controller 类名与厚度（如仅 1～3 行委托 + 校验注解 + 登录人，路由与序列化由 `§2` 页面主链路顺手覆盖）。
  3. **（仅分支模式）本次未改动且无调用波及的模块无需回归**：列明哪些老模块经 S0 确认零波及。
- **真正还需要做的**：1～3 件核心动作。

---

## §2 手工串联主链路（L2 真库 + L3 页面交互一次走完）
> - 全量模式：串起全系统从配置到终态的黄金闭环；
> - 分支模式：只串本次改动模块及其受波及的上下游节点，不拉无关模块陪跑。
> 测试同学照 Step 1 → Step N 在页面走一圈，顺手验完主链路上的「状态流转 + §3.1 真 SQL + §3.2 外部依赖 + 页面交互」。已在本节写清操作步骤的项，`§3` 和 `§4` 只引用 Step 编号，不重复抄操作。

- **Step 1【模块名 - 准备/配置】**：在什么页面 → 做什么操作 → 预期看到什么（顺手验 `§3.1 #X`、`§3.2 #X`）
- **Step 2【模块名 - 触发核心计算/生成】**：...
- **Step 3【模块名 - 异常/分支处理】**：...
- **Step 4【模块名 - 下游单据流转与终态回写】**：...

---

## §3 L2：真库与外部联调必验清单（单测 Mock 跳过的盲区）
> 以下高危点在单测里被 Mock 跳过，必须在测试环境真库/真服务跑过一次。能随 `§2` 主链路顺手触发的，操作列注明「随 `§2 Step X` 触发」，只写额外的数据前置与库表预期；主链路覆盖不到的标 `【独立加测】` 并写全三要素。

### §3.1 持久层真库盲区逐条核验表（4A 手写 XML/注解 SQL · 4B Wrapper/lambdaUpdate · 4C 软删唯一键/批量事务）
| # | 盲区类型 | 代码位置（`XML#id` 或 `Service#方法:行号`） | 关联 HTTP 接口 / 页面入口 | 为什么必须真库验（单测 Mock 漏在哪） | 具体怎么做（前置数据 → 操作步骤 → 预期结果） |
|---|---|---|---|---|---|
| 1 | 4A 手写 XML | `XxxDAO.xml#selectXxx` | `POST /xxx/list`（某页面某 Tab） | `LEFT JOIN` + `UNION ALL` 补集行、动态条件分支、手写 `is_deleted=0` | **前置**：准备有数据、无数据、已软删三类样本<br>**操作**：随 `§2 Step 2` 一起触发（或 `【独立加测】` 在某页面筛某条件）<br>**预期**：无数据行补 0 出现，软删不计入 |
| 2 | 4B Wrapper / `lambdaUpdate` | `XxxService#xxx` | `POST /xxx/reverse` | `.set(字段, null)` 被 deep stubs 吞掉；或裸 `.or()` 短路前置条件 | **前置**：...<br>**操作**：随 `§2 Step X` 触发（或 `【独立加测】` 触发反审/复合条件筛选）<br>**预期**：库表字段真正置回 `null` / 筛选结果不串数据 |
| 3 | 4C 软删重加唯一键 / `saveBatch` | `XxxBizService#delete/save` | `POST /xxx/delete` + `/save` | `@TableLogic` 软删后同业务键再新增是否撞 `uk_*`；主子表级联事务 | **前置**：已有 1 条记录<br>**操作**：`【独立加测】` 删除后立刻用相同业务键再新增 1 条<br>**预期**：新增成功，不报唯一键冲突 |

### §3.2 非 HTTP 入口（Job / MQ）与外部服务（Client）联调表
> 已与 `§3.1` 某行属同一次页面点击触发的 MQ/Client 直接并入 `§3.1`，不在此表重复列。

| # | 类型 | 类名与方法 | 关联入口 | 具体怎么验（操作步骤 → 预期结果） |
|---|---|---|---|---|
| 1 | 定时任务（`@XxlJob` 等） | `XxxJob#xxxHandler` | XXL-Job 控制台 / 调度入口 | **操作**：不传参跑一次 + 传指定参数跑一次<br>**预期**：任务成功无报错，下游表生成对应数据 |
| 2 | 外部依赖（`Client`） | `XxxClient` | 页面某下拉框 / 某按钮 | **操作**：随 `§2 Step X` 点下拉框，并额外填一个不存在的编码保存<br>**预期**：正常带出下游数据；异常编码触发拦截提示 |

## §4 L3：纯人工与阻塞专项（六大类，已在 §2 覆盖的直接注明，不重复抄）
> - 有 `*-自动化覆盖矩阵.md`：从「四态清单表」（`仅人工 / 无实现-阻塞 / 判据未定-阻塞`）和「覆盖矩阵明细表」半自动化 TC 备注列中的 `人工层 / 判据未定 / 【待确认】` 缺口归拢并带 TC 编号（备注为 `集成层 / 本层验不了 / 链式 mock 吞掉` 的归 `§3`）；
> - 只有源码：按 whitebox-recon 第二节的「仅源码识别法」反推。已在 `§2` 写清操作步骤的类别，直接写「已在 `§2 Step X` 覆盖，无额外独立项」；本范围未涉及的写「本范围无此类改动」。

| 类别 | 涉及模块与接口/TC 编号 | 具体操作与核对要点（点哪里 → 看什么） |
|---|---|---|
| 1. 真实文件往返（导出 / 导入 / 模板） | ... | 如已在 `§2 Step X` 覆盖则直接写明；有独立项时写清真 Excel 表头、单位括号、时间格式或错误回执列 |
| 2. 前端默认筛选值与控件形态（后端不兜底） | ... | 进入页面不手点筛选，看默认时间范围 / 默认状态是否选中并带参请求；下拉框单选/多选/模糊搜索/首项「全部」是否符合用例 |
| 3. 动态表单联动 / 字段显隐 / 动态列 | ... | 切换类型下拉时特定字段是否正确显示/隐藏/替换并带必填星号；列表动态列、动态 Tab 是否按配置渲染 |
| 4. 终态按钮置灰/隐藏 & 二次确认弹窗 | ... | 终态记录的操作按钮是否隐藏或置灰；确认框未勾选前按钮是否置灰；点击取消是否关闭弹窗且不发请求 |
| 5. Tooltip / 标签颜色 / 日志弹窗 | ... | 表头问号 icon 是否展示公式说明；不同状态标签颜色区分；点击「日志」是否弹出操作日志（未涉及则写「本范围无此类改动」） |
| 6. 【重点】无实现-阻塞 / 判据未定核查 | ...（如 `TC-xxxx` 或 `// @PostMapping` 位置） | 标注「后端无接口 / 未实现校验」的用例在页面实测是否有入口，有则提缺陷；【待确认】项现场拍板 |

## §5 L1：规则与纯口径单测（按「已有单测」或「尚未写单测」二选一）

> - **情况 A（已有单测）**：写明哪些模块的业务规则已被 N 条单测锁死，明确【不需要再从 HTTP 接口重测一遍，也不需要为纯透传 Controller 写接口脚本】；有红灯则列各模块红灯数及对应 `*-判据偏差清单.md`。
> - **情况 B（尚未写单测，只有源码）**：从源码中挑出最值得优先写单测的核心类与方法，列下表，并指出「这些分支组合用单测测，不要去测试环境用接口/手工硬造数据」。

| 模块 | 建议优先写单测的类与方法 | 包含的核心规则 / 计算分支 | 为什么用单测而不是接口/手工 |
|---|---|---|---|
| ... | `XxxCalculator#calc`、`XxxBizService#importXxx` | 如：换算进位规则、跨阶梯计费、逐行校验拦截 | 分支组合多，单测几秒跑完且幂等 |
```
