# 测试策略落盘模板

默认写入 `doc/testcases/{项目或模块}-测试策略.md`；分支模式建议带分支名 `doc/testcases/{模块}-{分支名}-测试策略.md`，避免多次迭代互相覆盖。项目无 `doc/testcases/` 则先创建；用户指定了目录就写到该目录。

**每一行待测项都由三部分组成：① 先准备什么数据、② 在页面点哪里（或调哪个接口/Job）、③ 看到什么现象算通过。** 测试同学拿到就能照着做，不需要再回头读代码；缺任何一部分这一行就还没写完。

## 编写规范（给 AI 看的规则，严禁把这些说明抄进生成的报告正文）

1. **章节导语只留一句话定位，不写排版规则**：每个章节标题下保留一行简短的 `> ...` 说明，告诉读者这一节测什么、怎么用；**严禁**把「已在本节写清的项不重复抄」「按情况 A/B 二选一」这类给 AI 看的排版指令写进最终报告。
2. **章节顺序（总览现状 → 页面操作 → 后台真库与Job → 开发补单测）**：
   - `§1 评估结论与测试取舍` → `§2 现状与范围盘点`（先交代本次涉及哪些模块、用例/单测家底与卡点）
   - `§3 核心业务场景验证` → `§4 纯人工与阻塞专项`（测试同学在页面上把核心业务场景和专项交互点完）
   - `§5 真库与外部联调必验清单`（核对真库落表、XXL-Job 与外部服务）
   - `§6 规则与纯口径单测`（开发补单测清单） → `§7 下一步行动顺序`
3. **`§3 核心业务场景验证`**：按本次改动涉及的独立业务场景逐条列出（`场景 1` ～ `场景 N`），不把互不相干的并行场景硬编成假装有先后顺序的 Step。只列本次改动及受波及模块的核心正向/主干场景，不拉无关老模块陪跑。
4. **`§3`、`§4`、`§5` 去重铁律（严禁同一动作抄三遍）**：
   - **`§3` vs `§4`**：`§4` 保留六大类 6 行骨架（有覆盖矩阵时从「四态清单表」和半自动化 TC 备注中的 `人工层 / 判据未定` 提取并带 TC 号；只有源码时按 whitebox-recon 第二节反推）。已在 `§3 场景 X` 完整验过的类别直接写 **`已在 §3 场景 X 覆盖，无额外独立项`**；本次改动完全不涉及的写 **`本范围无此类改动`**，严禁为填满表格编造凑数项。
   - **`§3` vs `§5.1`**：凡是走 `§3 核心业务场景` 就能顺手触发的真库 SQL 盲区，页面点击步骤只在 `§3 场景 X` 写一次；`§5.1` 保留该行，但「具体怎么做」列写成 **`操作：随 §3 场景 X 一起触发，不单独重走页面`**，只写该 SQL 额外要求的数据前置与落库字段核对。只有核心场景顺手覆盖不到的独立盲区（如软删重加、开关正反切）才标 **`【独立加测】`** 并在 `§5.1` 展开完整步骤。
   - **`§5.1` vs `§5.2`**：同一次页面点击同时触发 4A/4B/4C SQL 和 MQ/Client 的，合并在 `§5.1` 同一条写完，不在 `§5.2` 拆第二行。`§5.2` 只单列无页面入口的 `@XxlJob` / MQ 消费者，或需单独造异常入参的 `Client`。
5. **`§6 规则与纯口径单测`**：已有单测时写明哪些模块已被多少条单测锁死（有红灯则列红灯数及 `*-判据偏差清单.md`）；尚未写单测时从源码挑出最值得优先补单测的类与方法列表。

编号约定：`§N` = 本报告第 N 节；`SN` = whitebox-recon 第 N 步；`L1/L2/L3` = 三层模型。

## 模板正文

```markdown
# {项目或模块} 测试策略与可执行分工清单

## §1 评估结论与测试取舍
- **评估模式**：【仅当前分支改动（`{当前分支}` vs `{基准主干}`）】或【全量代码评估】。（非交互环境默认分支模式时，在此行标注「未经用户确认，默认按分支模式」）
- **项目/改动特征**：重计算规则 / 重复杂 SQL / 简单 CRUD / 外部接口联调（可组合）。
- **明确不需要做的**：
  1. **不需要用 HTTP 接口测试穷举纯计算/校验分支**：单测已覆盖（或应由 `§6` 单测覆盖），页面主链路跑 1 组代表数据即可。
  2. **不需要为纯透传 Controller 写接口契约脚本**：点明具体 Controller 类名与厚度（如仅 1～3 行委托 + 校验注解 + 登录人，路由与序列化由 `§3` 页面主链路顺手覆盖）。
  3. **（仅分支模式）本次未改动且无调用波及的模块无需回归**：列明哪些老模块经 S0 确认零波及。
- **真正还需要做的**：1～3 件核心动作。

---

## §2 现状与范围盘点

| 模块（是否本次改动/波及） | 接口数（本地 Controller / 线上文档如有） | 功能用例 | 规则/纯口径单测 | 当前卡点 / 缺口或漂移 |
|---|---:|---|---|---|
| ... | ... | 已有 N 条 / 未写 | 已写 N 条（红 M）/ 未写 | 如：有用例但本地缺代码 / M 条偏差见 `*-判据偏差清单.md` |

## §3 核心业务场景验证

| 场景 | 操作步骤 | 预期结果 |
|---|---|---|
| 1. 模块名 - 场景名 | 在什么页面 → 准备什么数据 → 做什么操作 | 看到什么结果（顺手验 `§5.1 #X`、`§5.2 #X`） |
| 2. 模块名 - 场景名 | ... | ... |
| 3. 模块名 - 场景名 | ... | ... |

## §4 纯人工与阻塞专项
> 单测和接口测不到、必须在页面人工核对的 6 类交互与阻塞项。

| 类别 | 涉及模块与接口/TC 编号 | 具体操作与核对要点（点哪里 → 看什么） |
|---|---|---|
| 1. 真实文件往返（导出 / 导入 / 模板） | ... | 如已在 `§3 场景 X` 覆盖则直接写明；有独立项时写清真 Excel 表头、单位括号、时间格式或错误回执列 |
| 2. 前端默认筛选值与控件形态（后端不兜底） | ... | 进入页面不手点筛选，看默认时间范围 / 默认状态是否选中并带参请求；下拉框单选/多选/模糊搜索/首项「全部」是否符合用例 |
| 3. 动态表单联动 / 字段显隐 / 动态列 | ... | 切换类型下拉时特定字段是否正确显示/隐藏/替换并带必填星号；列表动态列、动态 Tab 是否按配置渲染 |
| 4. 终态按钮置灰/隐藏 & 二次确认弹窗 | ... | 终态记录的操作按钮是否隐藏或置灰；确认框未勾选前按钮是否置灰；点击取消是否关闭弹窗且不发请求 |
| 5. Tooltip / 标签颜色 / 日志弹窗 | ... | 表头问号 icon 是否展示公式说明；不同状态标签颜色区分；点击「日志」是否弹出操作日志（未涉及则写「本范围无此类改动」） |
| 6. 【重点】无实现-阻塞 / 判据未定核查 | ...（如 `TC-xxxx` 或 `// @PostMapping` 位置） | 标注「后端无接口 / 未实现校验」的用例在页面实测是否有入口，有则提缺陷；【待确认】项现场拍板 |

## §5 真库与外部联调必验清单
> 以下高危点（手写 SQL、复杂 Wrapper、软删唯一键、定时任务与外部服务）在单测里被 Mock 跳过，必须在测试环境真库/真服务跑过一次。

### §5.1 持久层真库盲区逐条核验表
> 手写 XML/注解 SQL（4A）、Java 层复杂 Wrapper 与 `lambdaUpdate`（4B）、软删唯一键与批量写事务（4C）的真库落表核对清单。

| # | 盲区类型 | 代码位置（`XML#id` 或 `Service#方法:行号`） | 关联 HTTP 接口 / 页面入口 | 为什么必须真库验（单测 Mock 漏在哪） | 具体怎么做（前置数据 → 操作步骤 → 预期结果） |
|---|---|---|---|---|---|
| 1 | 4A 手写 XML | `XxxDAO.xml#selectXxx` | `POST /xxx/list`（某页面某 Tab） | `LEFT JOIN` + `UNION ALL` 补集行、动态条件分支、手写 `is_deleted=0` | **前置**：准备有数据、无数据、已软删三类样本<br>**操作**：随 `§3 场景 2` 一起触发（或 `【独立加测】` 在某页面筛某条件）<br>**预期**：无数据行补 0 出现，软删不计入 |
| 2 | 4B Wrapper / `lambdaUpdate` | `XxxService#xxx` | `POST /xxx/reverse` | `.set(字段, null)` 被 deep stubs 吞掉；或裸 `.or()` 短路前置条件 | **前置**：...<br>**操作**：随 `§3 场景 X` 触发（或 `【独立加测】` 触发反审/复合条件筛选）<br>**预期**：库表字段真正置回 `null` / 筛选结果不串数据 |
| 3 | 4C 软删重加唯一键 / `saveBatch` | `XxxBizService#delete/save` | `POST /xxx/delete` + `/save` | `@TableLogic` 软删后同业务键再新增是否撞 `uk_*`；主子表级联事务 | **前置**：已有 1 条记录<br>**操作**：`【独立加测】` 删除后立刻用相同业务键再新增 1 条<br>**预期**：新增成功，不报唯一键冲突 |

### §5.2 非 HTTP 入口（Job / MQ）与外部服务（Client）联调表
> 无页面入口的后台定时任务（`@XxlJob`）、MQ 消息以及跨服务 RPC（`Client`）的触发与容错核对清单。

| # | 类型 | 类名与方法 | 关联入口 | 具体怎么验（操作步骤 → 预期结果） |
|---|---|---|---|---|
| 1 | 定时任务（`@XxlJob` 等） | `XxxJob#xxxHandler` | XXL-Job 控制台 / 调度入口 | **操作**：不传参跑一次 + 传指定参数跑一次<br>**预期**：任务成功无报错，下游表生成对应数据 |
| 2 | 外部依赖（`Client`） | `XxxClient` | 页面某下拉框 / 某按钮 | **操作**：随 `§3 场景 X` 点下拉框，并额外填一个不存在的编码保存<br>**预期**：正常带出下游数据；异常编码触发拦截提示 |
```
