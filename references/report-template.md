# 测试策略落盘模板

默认写入 `doc/testcases/{项目或模块}-测试策略.md`；分支模式建议带分支名 `doc/testcases/{模块}-{分支名}-测试策略.md`，避免多次迭代互相覆盖。项目无 `doc/testcases/` 则先创建；用户指定了目录就写到该目录。

**每一行待测项都由三部分组成：① 先准备什么数据、② 在页面点哪里（或调哪个接口/Job）、③ 看到什么现象算通过。** 测试同学拿到就能照着做，不需要再回头读代码；缺任何一部分这一行就还没写完。

编号约定：`§N` = 本报告第 N 节；`SN` = whitebox-recon 第 N 步；`L1/L2/L3` = 三层模型。

---

## 模板正文

```markdown
# {项目或模块} 测试策略与可执行分工清单

## §1 一句话结论
- **评估模式**：【仅当前分支改动（`{当前分支}` vs `{基准主干}`）】或【全量代码评估】。（非交互环境默认分支模式时，在此行标注「未经用户确认，默认按分支模式」）
- **项目/改动特征**：重计算规则 / 重复杂 SQL / 简单 CRUD / 外部接口联调（可组合）。
- **明确不需要做的**：列出不需要做的测试类型与模块（分支模式还要点明哪些未改动老模块本次无需回归）及原因。
- **真正还需要做的**：1～3 件核心动作。

---

## §2 现状与范围盘点
> 分支模式：列本次 `git diff` 涉及的模块、新增/修改文件数及公共代码波及的老模块，未改动模块不列；全量模式：列全仓库模块。

| 模块（是否本次改动/波及） | 接口数（本地 Controller / 线上文档如有） | 功能用例 | L1 规则/纯口径单测 | 当前卡点 / 缺口或漂移 |
|---|---:|---|---|---|
| ... | ... | 已有 N 条 / 未写 | 已写 N 条（红 M）/ 未写 | 如：有用例但本地缺代码 / M 条偏差见 `*-判据偏差清单.md` |

---

## §3 L1：规则与纯口径单测（按「已有单测」或「尚未写单测」二选一）

> - **情况 A（已有单测）**：写明哪些模块的业务规则已被 N 条单测锁死，明确【不需要再从 HTTP 接口重测一遍，也不需要为纯透传 Controller 写接口脚本】；有红灯则列各模块红灯数及对应 `*-判据偏差清单.md`。
> - **情况 B（尚未写单测，只有源码）**：从源码中挑出最值得优先写单测的核心类与方法，列下表，并指出「这些分支组合用单测测，不要去测试环境用接口/手工硬造数据」。

| 模块 | 建议优先写单测的类与方法 | 包含的核心规则 / 计算分支 | 为什么用单测而不是接口/手工 |
|---|---|---|---|
| ... | `XxxCalculator#calc`、`XxxBizService#importXxx` | 如：换算进位规则、跨阶梯计费、逐行校验拦截 | 分支组合多，单测几秒跑完且幂等 |

### §3.1 明确【不需要做】的测试
1. **不需要用 HTTP 接口测试穷举 L1 的计算/校验分支**：单测已覆盖（或应由单测覆盖）。
2. **不需要为纯透传 Controller 写接口契约脚本**：写明 Controller 厚度（如仅 1～3 行委托 + 校验注解 + 登录人，页面主链路顺手覆盖）。
3. **（仅分支模式）本次未改动且无调用波及的模块无需回归**：列明哪些老模块经 S0 确认零波及。

---

## §4 L2：真库与外部联调必验清单（单测 Mock 跳过的盲区）
> 以下高危点在单测里被 Mock 跳过，必须在测试环境真库/真服务跑过一次。默认在页面手工操作覆盖；无页面入口或页面难造数据时用 Knife4j / XXL-Job 触发。

### §4.1 持久层真库盲区逐条核验表（4A 手写 XML/注解 SQL · 4B Wrapper/lambdaUpdate · 4C 软删唯一键/批量事务）
| # | 盲区类型 | 代码位置（`XML#id` 或 `Service#方法:行号`） | 关联 HTTP 接口 / 页面入口 | 为什么必须真库验（单测 Mock 漏在哪） | 具体怎么做（前置数据 → 操作步骤 → 预期结果） |
|---|---|---|---|---|---|
| 1 | 4A 手写 XML | `XxxDAO.xml#selectXxx` | `POST /xxx/list`（某页面某 Tab） | `LEFT JOIN` + `UNION ALL` 补集行、动态条件分支、手写 `is_deleted=0` | **前置**：准备什么数据<br>**操作**：在哪个页面/接口点什么、筛什么<br>**预期**：看到什么数据 / 不报什么错 |
| 2 | 4B Wrapper / `lambdaUpdate` | `XxxService#xxx` | `POST /xxx/reverse` | `.set(字段, null)` 被 deep stubs 吞掉；或裸 `.or()` 短路前置条件 | **前置**：...<br>**操作**：触发更新或带复合条件筛选<br>**预期**：库表字段真正置回 `null` / 筛选结果不串数据 |
| 3 | 4C 软删重加唯一键 / `saveBatch` | `XxxBizService#delete/save` | `POST /xxx/delete` + `/save` | `@TableLogic` 软删后同业务键再新增是否撞 `uk_*`；主子表级联事务 | **前置**：已有 1 条记录<br>**操作**：删除后立刻用相同业务键再新增 1 条<br>**预期**：新增成功，不报唯一键冲突 |

### §4.2 非 HTTP 入口（Job / MQ）与外部服务（Client）联调表
| # | 类型 | 类名与方法 | 关联入口 | 具体怎么验（操作步骤 → 预期结果） |
|---|---|---|---|---|
| 1 | 定时任务（`@XxlJob` 等） | `XxxJob#xxxHandler` | XXL-Job 控制台 / 调度入口 | **操作**：不传参跑一次 + 传指定参数跑一次<br>**预期**：任务成功无报错，下游表生成对应数据 |
| 2 | 外部依赖（`Client`） | `XxxClient` | 页面某下拉框 / 某按钮 | **操作**：打开页面点下拉框或触发按钮<br>**预期**：正常带出下游数据，无超时或序列化报错 |

---

## §5 手工串联主链路（L2 真库 + L3 页面交互一次走完）
> - 全量模式：串起全系统从配置到终态的黄金闭环；
> - 分支模式：只串本次改动模块及其受波及的上下游节点，不拉无关模块陪跑。
> 照 Step 1 → Step N 在测试环境页面走一圈，同时验完「状态流转 + §4.1 真 SQL + §4.2 外部依赖 + 页面交互」。

- **Step 1【模块名 - 准备/配置】**：在什么页面 → 做什么操作 → 顺手验哪两个点（注明对应 `§4.1 #X`）
- **Step 2【模块名 - 触发核心计算/生成】**：...
- **Step 3【模块名 - 异常/分支处理】**：...
- **Step 4【模块名 - 下游单据流转与终态回写】**：...

---

## §6 L3：纯人工与阻塞专项（六大类，每类至少一条或写明「本范围无此类」）
> - 有 `*-自动化覆盖矩阵.md`：从「四态清单表」（`仅人工 / 无实现-阻塞 / 判据未定-阻塞`）和「覆盖矩阵明细表」半自动化 TC 备注列中的 `人工层 / 判据未定 / 【待确认】` 缺口归拢并带 TC 编号（备注为 `集成层 / 本层验不了 / 链式 mock 吞掉` 的归 §4）；
> - 只有源码：按 whitebox-recon 第二节的「仅源码识别法」从 `export/import`、`SearchPO` 无默认值字段、`SavePO` 条件校验分支、`StatusEnum` 终态拦截、Controller 注释接口/TODO 反推。

| 类别 | 涉及模块与接口/TC 编号 | 具体操作与核对要点（点哪里 → 看什么） |
|---|---|---|
| 1. 真实文件往返（导出 / 导入 / 模板） | ... | ① 导出：打开真 Excel 核对表头、单位括号、时间格式、金额小数位；② 导入：传含合法+错误行的真文件，验 `taskId` 轮询与失败回执原因列；③ 模板下载：核对 Sheet 数与必填星号 |
| 2. 前端默认筛选值与控件形态（后端不兜底） | ... | 进入页面不手点筛选，看默认时间范围 / 默认状态是否选中并带参请求；下拉框单选/多选/模糊搜索/首项「全部」是否符合用例 |
| 3. 动态表单联动 / 字段显隐 / 动态列 | ... | 切换类型下拉时特定字段是否正确显示/隐藏/替换并带必填星号；列表动态列、动态 Tab 是否按配置渲染 |
| 4. 终态按钮置灰/隐藏 & 二次确认弹窗 | ... | 终态记录的操作按钮是否隐藏或置灰；确认框未勾选前按钮是否置灰；点击取消是否关闭弹窗且不发请求 |
| 5. Tooltip / 标签颜色 / 日志弹窗 | ... | 表头问号 icon 是否展示公式说明；不同状态标签颜色区分；点击「日志」是否弹出操作日志 |
| 6. 【重点】无实现-阻塞 / 判据未定核查 | ...（如 `TC-xxxx` 或 `// @PostMapping` 位置） | 标注「后端无接口 / 未实现校验」的用例在页面实测是否有入口，有则提缺陷；【待确认】项现场拍板 |
```
