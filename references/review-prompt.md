# 独立评审子 Agent 模板与 5 项核查维度

主 Agent 按 [report-template.md](report-template.md) 将初稿落盘到 `doc/testcases/{项目或模块}-测试策略.md` 后，必须派生 **1 个全新的独立评审子 Agent** 专查「漏项、越界与套话」（最多 1 轮，不落 `work/` 过程文件）。

---

## 一、派发约定

1. **子 Agent 类型**：优先使用只读/通用子 Agent（如 Cursor `generalPurpose` / `explore`、Claude Code `general-purpose`）。
2. **严禁自查替代**：只要运行环境支持子 Agent，必须派独立上下文的子 Agent 评审；仅在无子 Agent 工具的环境下，才退回由主 Agent 按下方 5 个维度逐条自检。
3. **只读禁令**：评审子 Agent 只负责用 Grep / Read 核查源码与覆盖矩阵并回传问题清单，严禁修改任何文件。

---

## 二、评审子 Agent Prompt 模板（填好花括号占位后整段发送）

```text
你是测试策略报告的独立评审员。你只负责挑刺并回传问题清单，严禁修改任何文件。

【输入信息】
- 被测项目根目录：{项目绝对路径}
- 本次评估范围：{仅当前分支改动（基准分支 <base>，分叉点 <mb>） / 全量代码}
- 待审测试策略报告：{doc/testcases/xxx-测试策略.md 绝对路径}
- 自动化覆盖矩阵（如有）：{覆盖矩阵绝对路径 或 无}
- 策略规则真值：{SKILL.md 绝对路径}、{references/whitebox-recon.md 绝对路径} 与 {references/report-template.md 绝对路径}

【请逐项核查以下 5 类高发缺陷（必须亲自用 Grep/Read 抽查源码与矩阵，不得只看报告字面）】
1. [SQL-n] 持久层真库盲区漏项：在评估范围内核对 `mapper/*.xml` 与 `.apply(` / `.last(` / `.or(` / `lambdaUpdate(` / `@TableLogic` 唯一索引 + `saveBatch`，报告 4.1 表是否有遗漏的高危 SQL/Wrapper？是否每条都反查到了具体的 HTTP 接口或 Job 入口？
2. [MAT-n] 覆盖矩阵缺口漏转（仅当有覆盖矩阵时）：核对矩阵的「四态清单表（仅人工/无实现-阻塞/判据未定）」及「覆盖矩阵明细表中 `明细行 > 可自动化行` 的半自动化 TC 备注列」，是否有备注为 `集成层 / 本层验不了 / 链式 mock 吞掉` 的条目漏进了第 4 节，或备注为 `人工层 / 判据未定` 的条目漏进了第 6 节？
3. [EXEC-n] 可执行性套话：检查 4.1 表、4.2 表、第 5 节主链路、第 6 节人工表，指出所有未写清「前置数据 → 操作步骤 → 预期结果」、只写「验证 SQL 正确性 / 验证功能正常 / 符合预期」等笼统空话的行号与条目。
4. [SCOPE-n] 违背「不硬凑」或范围越界：
   - 对已有规则层单测锁死且 Controller 仅为 1～3 行纯透传的模块，报告是否违规建议去写全量 HTTP 接口测试？
   - 若为「仅当前分支改动」模式，报告第 2/4/5/6 节是否混入了本次未改动且不在公共代码调用波及链上的老模块？
5. [MAN-n] 第三层 6 大类残缺：第 6 节是否漏掉了「1.文件往返、2.前端默认筛选值与控件形态、3.动态表单联动/动态列、4.终态按钮置灰与确认弹窗、5.Tooltip/标签颜色/日志弹窗、6.无实现-阻塞/判据未定核查」中的任何一类（或未从源码/矩阵中挖出对应具体条目）？

【输出格式】
- 结论：通过 / 需修改
- 问题清单（若通过则为无）：按 `[类别编号] 报告章节/行号：问题描述 → 源码/矩阵证据 → 应如何补齐` 逐条列出。
```

---

## 三、主 Agent 修复与交付规则（最多 1 轮）

- **若评审结论为「通过」**：直接在对话中向用户输出精炼结论与报告路径。
- **若评审结论为「需修改」**：主 Agent 核实清单中的有效问题（剔除误报），直接在 `doc/testcases/{项目或模块}-测试策略.md` 上一次性修完，**禁止开启第 2 轮评审**，修完后直接在对话中给出精炼结论与报告路径。
